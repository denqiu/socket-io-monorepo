### **Why Use Both RuleTester and a Demo Folder?**

When developing ESLint plugins and rules, using both **RuleTester** and a **demo folder** ensures comprehensive testing. These two approaches align with the principles of **unit testing** and **integration testing**, providing thorough validation of rule behavior.

---

### **Unit Testing with RuleTester**
#### **What is RuleTester?**
`RuleTester` is a utility provided by ESLint to test rules in isolation. It runs tests against the core logic of a rule using defined `valid` and `invalid` cases.

#### **Why Use RuleTester?**
- **Isolated Testing**:
  - RuleTester focuses on the rule logic without external dependencies or configurations.
  - This helps ensure the rule behaves correctly in a controlled environment.
- **Fast Feedback**:
  - Unit tests with RuleTester are lightweight and execute quickly, providing immediate feedback.
- **Edge Case Validation**:
  - You can define precise test cases to cover edge scenarios, like complex AST structures or rare usage patterns.

#### **Example**
```javascript
ruleTester.run("no-foo", myRule, {
  valid: ["const bar = 42;"],
  invalid: [
    {
      code: "const foo = 42;",
      errors: [{ messageId: "noFooError" }],
    },
  ],
});
```

#### **Benefits of Unit Testing**
- Ensures rule logic is correct at a granular level.
- Provides confidence that individual rules work as intended before integration.

### **Integration Testing with a Demo Folder**
#### **What is a Demo Folder?**
A demo folder contains example files that mimic real-world scenarios where your plugin and rules are applied.

#### **Why Use a Demo Folder?**
- **Real-World Validation**:
  - Tests how the plugin behaves in an actual project environment.
  - Verifies that configurations (e.g., parser options, overrides) are respected.
- **Integration Testing**:
  - Ensures rules interact correctly with other plugins or ESLint configurations.
  - Validates that error messages and auto-fixes are user-friendly and intuitive.
- **User Perspective**:
  - Simulates how end-users will experience the plugin in their workflows.

#### **Example**
1. Add example files to the `demo/` folder:
   ```javascript
   // demo/file1.js
   const foo = 42;
   ```

2. Lint the demo folder using your plugin:
   ```bash
   npx eslint demo/
   ```

3. Verify the output:
   - Ensure errors are reported where expected.
   - Confirm that fixes are applied correctly.

#### **Benefits of Integration Testing**
- Tests the plugin as a whole, not just individual rules.
- Identifies issues that may arise from configuration or rule interactions.

### **Unit Testing vs. Integration Testing**

#### **Unit Testing**
- Focuses on **individual components** (rules in this case).
- Provides precise feedback on rule logic.
- Example: Testing that `const foo = 42;` is flagged as invalid with the correct error message.

#### **Integration Testing**
- Focuses on **system behavior** (plugin behavior as a whole).
- Ensures the plugin works as expected with configurations, real files, and user workflows.
- Example: Running ESLint on a project folder and confirming errors and fixes align with expectations.
